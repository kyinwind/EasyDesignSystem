# EasyDesignSystem 按钮组件盘点报告

日期：2026-09-20
盘点范围：`Sources/EasyDesignSystem`（公开 API 面）+ `Examples/*`（实际用法）
目标：为「按钮组件标准化、专业化」改造提供事实基线

---

## 一、结论摘要

三句话：

1. **真正的按钮只有 4 种**，全部由 `EDSButton.Role` 一个枚举驱动（`primary` / `secondary` / `soft` / `danger`），且四者都是「视觉样式」维度，**没有任何尺寸、形态、状态维度**。
2. **另有 6 处元素在承担按钮职责但没有走按钮体系**（侧边栏项、Pill、折叠头、Pill 删除叉、状态页动作等），各自用 `.plain` + 现写逻辑，行为不一致。
3. **最要命的不是"种类少"，而是"Role 把视觉分量和业务语义混在一个枚举里"**。`soft` 说的是"视觉轻"，`danger` 说的是"语义危险"，两者不在同一个维度上，却被并列成同级选项。这是当前设计最不专业的一处，也是统一改造必须动的根。

## 二、按钮清单

### 2.1 正式按钮：`EDSButton`（唯一入口）

文件：`Sources/EasyDesignSystem/EDSButtons.swift:155-219`

| # | Role | 配套 ButtonStyle | 视觉表现 | 定义位置 |
| --- | --- | --- | --- | --- |
| 1 | `.primary` | `EDSPrimaryButtonStyle` | `colors.primary` 实心填充 + 白字 | `EDSButtons.swift:5` |
| 2 | `.secondary` | `EDSSecondaryButtonStyle` | 1.5pt `primary` 描边 + 主题色字 | `EDSButtons.swift:42` |
| 3 | `.soft` | `EDSSoftButtonStyle` | `accentSoft`（=accent 12%）填充 + 主题色字 | `EDSButtons.swift:79` |
| 4 | `.danger` | `EDSDangerButtonStyle` | `colors.danger` 实心填充 + 白字 | `EDSButtons.swift:116` |

两个 init：

- `EDSButton(_ role: Role = .primary, action:, label:)` — 自定义 label
- `EDSButton(_ title: LocalizedStringKey, role:systemImage:action:)` — 文本/图标+文本

**全部公开 API 计数：4 个 Role、4 个 ButtonStyle、1 个容器 View、2 个 init。**

### 2.2 四个 ButtonStyle 的内部实现

`EDSButtons.swift:5-151`，**共 147 行，四份几乎逐行复制**。每份都做同样的事：

```swift
@Environment(\.isEnabled) / \.edsTheme / \.edsInteractionProfile
@Environment(\.horizontalSizeClass) / \.accessibilityReduceMotion
@State private var isHovered = false

EDSResolvedMetrics.resolve(...)              // 4 行落点完全一致
label
  .edsFont(.bodyStrong, tokens:)             // 一致
  .foregroundColor(<唯一差异点>)              // ← 只有这一行和 background 不同
  .frame(minHeight: metrics.interactiveHeight(for: theme.controlSize.buttonHeight))
  .padding(.horizontal, theme.spacing.md)    // 一致
  .background(<唯一差异点>)
  .contentShape(RoundedRectangle(cornerRadius: theme.radius.md))
  .opacity(isEnabled ? (showsHover ? 0.85 : 1.0) : 0.5)
  .scaleEffect(configuration.isPressed && !reduceMotion ? 0.97 : 1.0)
  .animation(reduceMotion ? nil : .easeInOut(duration: 0.15), value: isHovered)
  .onHover { isHovered = $0 }
```

四份之间**真正的差异只有 2 行**（前景色 + 背景）。其余约 20 行是四倍冗余——加一个 size 参数就要改四处，加一个 focus 态就要改四处。

### 2.3 承担按钮职责、但未走按钮体系的元素

| # | 组件 | 位置 | 交互实现 | 问题 |
| --- | --- | --- | --- | --- |
| 5 | `EDSSidebarItemButton` | `EDSSurfaces.swift:125-165` | `Button` + `.plain` | 自算 metrics、自定圆角 `radius.sm`、自定选中态；与按钮体系零共享 |
| 6 | `EDSPill` | `EDSPills.swift:130-222` | **`onTapGesture`**（不是 Button） | 靠手写 `EDSPillAccessibilityModifier` 补 `.isButton` trait；无键盘/开关控制支持；无 focus 环 |

## 三、问题清单（按严重度）

### P0-1 · 结构：Role 混装两个正交维度

```
当前（一维，语义与分量混在一起）：
  .primary   ← 分量：最强
  .secondary ← 分量：中等（描边）
  .soft      ← 分量：最轻
  .danger    ← 语义：破坏性   ← 跟前三个不在一个维度！
```

后果：

- 想要「**次要但危险**」（对话框里的"忽略并删除"）→ 无解。`.danger` 只有实心最强档，跟主操作抢视觉权重；用 `.secondary` 又丢了危险语义。
- 想要「**轻量主操作**」（工具栏里的主按钮）→ 无解。
- 想要「**成功语义按钮**」（"确认收货"）→ 无解，`success` / `warning` 有颜色 token 却没有按钮档位。
- 想要「**纯文本按钮**」（卡片右上角"更多"、设置页"清除缓存"）→ 无解，最轻的 `.soft` 也带底色块。

专业设计系统的通行做法是拆成两个维度：`emphasis`（视觉分量：filled / outline / soft / plain）× `tone`（语义色：accent / danger / neutral）。

### P0-2 · 一致性：硬编码穿透主题

| 位置 | 硬编码 | 后果 |
| --- | --- | --- |
| `EDSButtons.swift:25, 136` | `.foregroundColor(.white)` | 主题把 `primary` / `danger` 换成浅色（黄、亮青）时文字直接看不见。缺 `onPrimary` / `onDanger` 前景 token |
| `EDSButtons.swift:67` | `lineWidth: 1.5` | 绕开了 `theme.stroke.hairline`，描边宽度不可主题化 |
| `EDSButtons.swift:34` | `scaleEffect(0.97)` | 按压缩放系数是魔数，未进 token |
| `EDSButtons.swift:35` | `.easeInOut(duration: 0.15)` | 动效时长四处重复，未进 token |
| `EDSButtons.swift:33, 144` | `opacity(0.5)` 禁用态 | 禁用/悬停两档透明度都是魔数 |
| `EDSPills.swift:204, 206` | `font(size:13)`、`frame(16,16)` | 删除叉的尺寸全硬编码 |

### P1-1 · 能力缺口（7 项）

| 缺什么 | 影响 |
| --- | --- |
| **尺寸变体** | `EDSControlSizeTokens` 只有 `buttonHeight = 34` 一个值。工具栏/卡片内需要 28，主 CTA/触屏需要 44+。调用方只能自己 `.frame` 覆盖，破坏一致性 |
| **Icon-only 按钮** | 完全缺失。`EDSSidebarIcon` 是装饰不可点，Pill 删除叉是私有的。任何"工具栏图标按钮""关闭按钮"都得现造 |
| **Loading 态** | 完全缺失。异步提交时调用方要么禁用按钮丢反馈，要么自己塞 `ProgressView` 破坏排版 |
| **全宽 / 拉伸变体** | 缺失。移动端表单主 CTA 通常要 `maxWidth: .infinity`，现在得在外面包 `.frame` |
| **Text-only（无底色）** | 缺失。见 P0-1 |
| **Focus 环（键盘导航）** | 只有 `onHover`，**没有任何 `@FocusState` / focus ring**。macOS 上用 Tab 键走不到按钮，或走到了看不出焦点在哪。这是 macOS 原生 App 的硬伤，也是当前"不够专业"最直观的一条 |
| **禁用语义** | 只有 `opacity(0.5)`，无 `accessibilityAddTraits(.isNotEnabled)` |

### P1-2 · 无障碍 / 平台规范

- `EDSPill` 用 `onTapGesture` 而非 `Button` → 键盘无法聚焦、开关控制（Switch Control）无法操作，靠手写 modifier 打补丁（`EDSPills.swift:224-244`）。
- `EDSButton` 无 `accessibilityHint` 参数；`EDSPill` 的删除叉硬编码中文提示 `"删除 \(title)"`（`EDSPills.swift:215-216`）——**未走本地化**，与包内 `Localizable.strings` 体系不一致。
- 触控目标：`EDSButton` 正确调用了 `metrics.interactiveHeight(for:)`；但 `EDSSidebarItemButton`、`EDSCollapsibleSection` 各自处理，无统一兜底。

### P2-1 · 命名不统一

| 组件 | 变体枚举名 | 值风格 |
| --- | --- | --- |
| `EDSButton` | `EDSButton.Role` | 表分量 + 语义混装 |
| `EDSBadge` | `EDSBadge.Style` | 表语义（neutral/accent/success…） |
| `EDSPill` | `EDSPillTone`（是 struct，不是 enum！） | 是「前景/背景/边框三色对象」，语义完全不同 |
| `EDSSidebarItemButton` | 无枚举 | 靠 `isSelected: Bool` |
| `EDSSidebarIcon` | `IconSize` | 表尺寸 |

同样是"样式选项"，四个组件四个叫法，调用方没有可迁移的心智模型。

### P2-2 · 边界重叠

`EDSToggle`（`EDSButtons.swift:403`）自带「label + Spacer + 控件 + vertical padding」，实质是**行组件**，与 `EDSSettingRow`（`EDSRows.swift:5`）功能重叠。按 EDS 自己的分层原则（`EDSRows` 管行、`EDSButtons` 管控件），`EDSToggle` 放错了文件，且违反"组件只做自己的事"。

## 四、统一方向建议（待杨哥确认后展开成完整方案）

### 4.1 核心：把一维 Role 拆成三维

```
emphasis（分量）: .filled  .outline  .soft  .plain
tone（语义）    : .accent  .neutral  .danger  .success  .warning
size（尺寸）    : .small(28)  .medium(34)  .large(44)
```

组合示例：

```swift
EDSButton("保存", emphasis: .filled,  tone: .accent)   // = 现 .primary
EDSButton("取消", emphasis: .outline, tone: .accent)   // = 现 .secondary
EDSButton("忽略", emphasis: .soft,    tone: .neutral)  // = 现 .soft
EDSButton("删除", emphasis: .filled,  tone: .danger)   // = 现 .danger
EDSButton("全部删除", emphasis: .soft, tone: .danger)  // ← 新能力：次要但危险
EDSButton("更多", emphasis: .plain,   tone: .accent)   // ← 新能力：纯文本
EDSButton("确定", emphasis: .filled,  tone: .accent, size: .large)  // ← 新能力：尺寸
EDSIconButton(systemName: "xmark", tone: .neutral)     // ← 新能力：图标按钮
```

### 4.2 实现：单一风格驱动

把 147 行四份复制收敛成 **1 份 `EDSButtonStyle` + 1 个 `EDSButtonAppearance` 值对象**（承载 emphasis/tone/size/pressed/hovered/disabled 解析结果）。四个旧 ButtonStyle 保留为 thin wrapper 转发，标记 deprecated 但**不删**。

### 4.3 需要新增的 token

| Token | 用途 | 替换掉 |
| --- | --- | --- |
| `colors.onPrimary` / `onDanger` / `onAccent` | 实心填充上的文字色 | `.white` 硬编码 |
| `controlSize.buttonHeights`（small/medium/large） | 三档按钮高 | 单一 `buttonHeight` |
| `controlSize.buttonPaddingH`（三档） | 三档横向内边距 | 恒定 `spacing.md` |
| `controlSize.iconButtonSize` | 图标按钮边长 | 无 |
| `motion.pressScale` / `motion.hoverOpacity` / `motion.duration` | 交互反馈参数 | 0.97 / 0.85 / 0.5 / 0.15 魔数 |
| `effects.focusRingColor` / `focusRingWidth` | macOS 键盘焦点环 | 无 |

### 4.4 兼容策略

- **零破坏**：`EDSButton.Role` 及 4 个 ButtonStyle 全部保留、行为不变，内部改为转发到新实现。
- README 的 6 处 `EDSSettingRow` 示例、Examples 三个 Gallery、Tests —— 不改也能编译。
- 版本位：`0.2.1` → `0.3.0`（引入新对外模型，符合 CHANGELOG 已固化的判据）。
