## 一、为什么要出 0.3.1

0.3.0 交付了按钮三维模型，但 VideoHero 迁移排查暴露了两个必须先在包内解决的问题。**两者都不是"改按钮设计"，是补齐缺陷与适配能力。**

| # | 问题 | 性质 | 阻塞 VideoHero 迁移？ |
| --- | --- | --- | --- |
| **A1** | `accent` 与 `primary` 职责重叠，包内读取点分裂 | 包内真实缺陷 | ❌ 不阻塞（VideoHero 改 `applyPreset` 后自愈） |
| **A2** | `EDSButton` 不接受 `String` 标题，App 侧本地化函数无处可用 | 包内能力缺口 | ✅ **硬阻塞**（50 处迁移写法全部受影响） |

**结论：A1 可独立排期，A2 必须随 0.3.1 一起发，否则 VideoHero 迁移无法用干净写法落地。**

## 二、A1 · `accent` 与 `primary` 职责重叠

### 2.1 问题

`EDSColorTokens` 有两个独立的"主题色"字段，默认值都是 `.blue`：

```swift
public var primary: Color = .blue
public var accent: Color = .blue
```

**所有预设都把两者设成同一个值**（已核实）：

| 预设 | primary | accent |
| --- | --- | --- |
| `.default` / `.blue` | `#3185FF` | `#3185FF` |
| `.orange` | `#FF6B00` | `#FF6B00` |
| `.purple` | `#8B5CF6` | `#8B5CF6` |

但**包内对这"同一个概念"的读取是分裂的**——有的地方读 `primary`，有的地方读 `accent`：

| # | 位置 | 读取 | 后果 |
| --- | --- | --- | --- |
| 1 | `EDSButtons.swift:358` `tone .accent` → `toneColor` | `colors.primary` | ✅ 跟随 primary |
| 2 | `EDSButtons.swift:368` `tone .accent` → `toneSoftColor` | `colors.accentSoft` → `colors.accent` | ❌ 不跟随 |
| 3 | `EDSSurfaces.swift:158` `EDSSidebarItemButton` 选中底色 | `colors.accentSoft` | ❌ 不跟随 |
| 4 | `EDSSurfaces.swift:163` `EDSSidebarItemButton` 选中字色 | `colors.accent` | ❌ 不跟随 |
| 5 | `EDSEasyDesign.swift:270` `.tint()` | `colors.accent` | ❌ 不跟随 |

### 2.2 最小复现（VideoHero 现状）

`VideoHeroApp.swift:142` 只写：

```swift
EDSTheme.shared.configure { tokens in
    tokens.colors.primary = .orange     // 只改了 primary
}
```

后果：

- `EDSButton("x", emphasis: .soft)` → **12% 蓝底 + 橙字**（2 读 primary 做字色，5 里的 accentSoft 做底色）
- 设置页侧边栏选中项 → **蓝色**（3、4）
- 全局 `.tint()` → **蓝色**（5）

**这是当前线上就存在的视觉 bug，不是改造引入的。**

### 2.3 修复方案（杨哥已决议：方案 A）

**统一读 `primary`，`accent` 字段保留但包内不再读取。**

具体改动 4 处：

```swift
// ① EDSDesignTokens.swift:107
// 旧：public var accentSoft: Color { accent.opacity(0.12) }
public var accentSoft: Color { primary.opacity(0.12) }

// ② EDSSurfaces.swift:158
.fill(isSelected ? theme.colors.accentSoft : Color.clear)   // accentSoft 已改指向 primary，此处不变

// ③ EDSSurfaces.swift:163
.foregroundStyle(isSelected ? theme.colors.primary : theme.colors.textPrimary)

// ④ EDSEasyDesign.swift:270
.tint(tokens.colors.primary)
```

`EDSButtons.swift:368` 无需改动——它读 `colors.accentSoft`，而该计算属性已改为指向 `primary`。

### 2.4 为什么保留 `accent` 字段而不删除

| 原因 | 说明 |
| --- | --- |
| **Codable 兼容** | `EDSDesignTokens` 是 `Codable`，Theme JSON 里有 `accent` 键。删除会破坏自定义主题 JSON 解析 |
| **零破坏承诺** | 删除公开存储属性 = API 断裂，与项目"零破坏性变更优先"约定冲突 |
| **过渡期可观测** | 保留字段可让"只改 accent 的 App"至少不报错，只是改动不再生效 |

### 2.5 兼容性影响

| 调用方类型 | 影响 | 说明 |
| --- | --- | --- |
| 用 `applyPreset(_:)` 的 App | ✅ **零视觉变化** | 预设本来 primary == accent |
| 只改 `primary` 的 App（VideoHero） | ✅ **修复 bug** | 蓝底蓝 tint 变橙，这是期望行为 |
| 只改 `accent` 的 App | ⚠️ **改动失效** | 需盘点：目前已知 VideoHero 只改 primary，其他 App 待确认 |

### 2.6 待杨哥确认

**你手上其他 App（TTSMate / RightClickMate / 诵经助手系列）有没有写过 `tokens.colors.accent = ...`？**

- 如果**没有** → 方案 A 零风险，直接做
- 如果**有** → 需要把那处一并改成 `primary`（改动本身无害，因为预设里两者本来就同色）

> 我的判断：大概率没有。因为 `accent` 这个名字在文档里没被提过，而 `primary` 是 README 里唯一出现的主题色。但这个不能替你猜，得搜一遍。

### 2.7 顺带的文档修正

`EDSDesignTokens.swift` 里 `accent` 的注释需补一句：**"包内不再读取；如需变更主题色，请改 `primary`。"** 这是把隐患变成显式约定。

## 三、A2 · `EDSButton` 新增 `String` 标题重载

### 3.1 问题（实测证据）

VideoHero 的本地化函数返回 `String`：

```swift
// VideoHero/Components/L10n.swift:5
nonisolated func L(_ key: String, _ args: CVarArg...) -> String
```

而 `EDSButton` 的标题参数是 `LocalizedStringKey`。实测编译结果：

```
error: cannot convert value of type 'String' to expected argument type 'LocalizedStringKey'
```

**所以 `EDSButton(L("button.cancel"), role: .secondary) {}` 编译失败。**

### 3.2 VideoHero 现在是怎么绕开的

现有 2 处 EDSButton 全部使用 **label 闭包**形式，正好绕开了这个限制：

```swift
// MainView.swift:487
EDSButton(.primary, action: {
    togglePlayback()
}, label: {
    Label(isPlaying ? L("player.pause") : L("player.play"), systemImage: ...)
})
```

`Label` 接受 `StringProtocol`，所以能过。但**标题式写法（`EDSButton("文案", role:)`）迁移时用不了**——50 处里绝大多数是标题式。

### 3.3 候选方案对比

| 方案 | 写法 | 需改包 | 问题 |
| --- | --- | --- | --- |
| **A. 加 String 重载** | `EDSButton(L("x"), role: .secondary) {}` | ✅ 需 0.3.1 | 需验证不破坏现有调用（已验，见 3.4） |
| B. 调用侧包一层 | `EDSButton(LocalizedStringKey(L("x")), role: .secondary) {}` | ❌ | 50 处都要加噪音，且二次查表 |
| C. 全用 label 闭包 | `EDSButton(.secondary, action: {...}, label: { Text(L("x")) })` | ❌ | 冗长，可读性差 |
| D. App 侧薄封装 | `EDSBtn(L("x"), role: .secondary) {}` | ❌ | 多一层间接，且每个 App 都要自己写 |

**推荐 A。** 理由：

1. **不是 VideoHero 的特例**——任何用自己的本地化系统（返回 `String`）的 App 都会踩
2. **`EDSBadge` 已有先例**：`init(_ text: LocalizedStringKey, style:)` 与 `init(_ text: String, style:)` 并存（`EDSButtons.swift:555/561`），`EDSButton` 缺这一致性
3. 迁移写法最干净

### 3.4 安全性验证（已实测，非推理）

用等价签名做了重载决议实验（`/tmp/ovl2.swift`），结果**零错误**：

```swift
// A 组：现有写法必须一字不改地继续编译 —— 全部通过
EDSButton("确定", role: .primary) { }
EDSButton("取消", role: .secondary, systemImage: "xmark") { }
EDSButton(.secondary, action: { }, label: { Text("x") })

// B 组：新增 String 支持 —— 全部通过
EDSButton(stringVar, role: .primary) { }
EDSButton(stringVar) { }
EDSButton(stringVar, emphasis: .filled) { }

// C 组：三维字面量 —— 通过
EDSButton("确定", emphasis: .filled, tone: .danger, size: .small) { }
```

**关键结论：`String` 与 `LocalizedStringKey` 重载并存时，字符串字面量调用不产生 ambiguity**——Swift 会稳定选中 `LocalizedStringKey` 版本。这解释了为什么 `EDSBadge` 的双重载一直没问题。

### 3.5 改动内容

新增两个 init（与既有两个平行，仅首参类型不同）：

```swift
/// 支持外部项目直接传入 `String` 变量（如 App 自有本地化函数 `L()` 的返回值）。
///
/// 与 `LocalizedStringKey` 重载并存安全：字面量调用稳定命中后者，不会产生歧义。
public init(
    _ title: String,
    role: Role = .primary,
    systemImage: String? = nil,
    action: @escaping () -> Void
)

/// 同上，三维入口的 `String` 版本。
public init(
    _ title: String,
    emphasis: Emphasis,
    tone: Tone = .accent,
    size: Size = .regular,
    systemImage: String? = nil,
    action: @escaping () -> Void
)
```

内部实现复用既有逻辑（与 `EDSBadge` 的 `.localized(LocalizedStringKey(text))` 策略一致）：

```swift
self.init(LocalizedStringKey(title), role: role, systemImage: systemImage, action: action)
```

### 3.6 对 VideoHero 的直接影响

迁移写法从"做不到"变成"一行直译"：

```swift
// 改造前
Button(L("button.cancel")) { onCancel() }
    .buttonStyle(.bordered)

// 改造后
EDSButton(L("button.cancel"), role: .secondary) { onCancel() }
```

## 四、版本与发布

| 项 | 值 | 依据 |
| --- | --- | --- |
| 版本号 | **0.3.1**（patch） | 无公开符号删除；`accent` 字段保留；新增重载属兼容扩展。行为变更仅"修复 bug"性质 |

> ⚠️ **VideoHero 的依赖约束是 `upToNextMajorVersion` + `minimumVersion = 0.3.0`**，所以 0.3.1 发布后 VideoHero **不需要改依赖声明**，重新解析即可拿到。

## 七、与 VideoHero 迁移的衔接

| | 依赖 0.3.1 的哪部分 |
| --- | --- |
| 主题配置改 `applyPreset(.orange)` | 不需要（0.3.0 即可） |
| 标准动作按钮批量替换 | **A2 必需**（否则只能写 label 闭包形式） |
| `soft` 档 / 侧边栏 / tint 正确跟随主题 | 不需要（`applyPreset` 后 primary == accent，天然一致）；A1 是**长期加固** |

**建议顺序：先发 0.3.1，再动 VideoHero 迁移。** 理由：迁移要动约 50 处，应当一次到位；先补完包内能力，避免迁完再升版本重新验一遍。
