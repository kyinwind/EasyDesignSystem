# EasyDesignSystem 0.5.4 字体 Token 生效修复方案和开发计划

> 创建日期：2026-10-05  
> 目标版本：0.5.4  
> 状态：实施中

## 一、问题与根因

`EDSTypographyTokens` 已声明 `heroSize`、`pageTitleSize`、`sectionTitleSize`、`bodySize` 等字号，但 `edsFont` 当前只读取字重，并把角色直接映射为 SwiftUI 系统语义字体。数值字号没有参与最终 `Font` 构造。

在当前 macOS 上，`.subheadline` 的实际字号小于 `.body`，因此 `sectionTitleSize = 15` 的区块标题实际显示为约 11pt，而 `bodySize = 13` 的正文显示为约 13pt，造成标题反而小于正文。

这是 EasyDesignSystem 的字体解析实现问题，不是调用方使用 `EDSGroup` 或 `EDSSectionTitle` 的问题。

## 二、设计方案

- 为内部字体规格增加 `size`，每个 `EDSFontRole` 读取对应的 `*Size` token。
- `EDSScaledFontModifier` 使用 `@ScaledMetric(relativeTo:)`，以 token 数值为基准并保留系统动态字体缩放。
- 最终字体使用 `.system(size:weight:design:)` 构造，字号、字重和字体设计全部由 token 驱动。
- 保持既有公开 API、角色名称和默认 token 数值不变。
- 默认层级保持：Hero 30、页面标题 17、区块标题 15、正文 13、副标题 12、等宽说明 11。

## 三、数据库及持久化

**无数据库变更。** 本次修改仅影响 SwiftUI 字体解析，不涉及数据库模型、UserDefaults、主题 JSON 结构或迁移逻辑。

已有主题 JSON 中的字号字段无需迁移；修复后这些既有字段会首次正确影响 `edsFont` 的渲染结果。

## 四、界面变化

- 使用 `edsFont` 的内置组件将按声明的 Typography token 显示。
- 区块标题会恢复为 15pt 基准并明显高于 13pt 正文。
- 页面标题、Hero、body15、caption 等此前被系统语义字体替代的角色也会恢复各自声明的尺寸。
- 动态字体缩放继续生效，不采用不可缩放的固定字号。

## 五、修改文件

- `Sources/EasyDesignSystem/EDSScaledTypography.swift`：修复字体规格和缩放实现。
- `Tests/EasyDesignSystemTests/EasyDesignSystemTests.swift`：增加字体角色到字号 token 的回归测试。
- `CHANGELOG.md`：增加 0.5.4 修复记录。
- `docs/20261005EDS0.5.4字体Token生效修复方案和开发计划.md`：记录分析、实施和验证结果。

不新增业务源码文件，不修改公共 API 基线。

## 六、风险

- 这是向后兼容的 Bug 修复，但会改变所有使用 `edsFont` 组件的实际视觉尺寸。
- Hero、页面标题、body15 的变化可能比 sectionTitle 更明显，需要通过 Catalog 和调用方 App 做肉眼验收。
- 自定义主题若曾依赖“字号字段不生效”的旧行为，会在升级后恢复其配置值；这是预期修复，但应写入 Changelog。
