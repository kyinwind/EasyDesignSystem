# EasyDesignSystem 改动需求（SettingsSuite 前置依赖）

日期：2026-09-16
提出方：SettingsSuite（新设置页编排包，依赖 EDS 公开版）
执行方：EDS 仓维护者（Codex）
预估改动量：约 15 行，纯可见性提升 + 1 处可选新增 API

---

## 一、背景与动机

SettingsSuite 是一个新建的 SwiftUI 设置页编排包，用于统一 MichaelDev 系列 App（TTSMate / VideoHero / 诵经助手等）的设置界面。它**依赖 EasyDesignSystem**（照 `SwiftHelpCenter/Package.swift` 既有写法：`.package(url: "https://github.com/kyinwind/EasyDesignSystem.git", .upToNextMinor(from: "0.2.0"))`）。

按架构分工约定：

> **能脱离"设置场景"复用的能力归 EDS；只在设置场景成立的归 SettingsSuite。**

据此确定：SettingsSuite **不使用** `EDSSettingRow` / `EDSValueRow`（它们是 EDS 的展示型行组件），而是用 EDS 的**底层能力**自己组装设置场景专属的行组件（需要支持点击动作、chevron、hover 高亮、推入导航等 EDS 行组件没有的能力）。

问题在于：自己组装所必需的**三个底层能力目前是 `internal`，上层包拿不到**。若不解决，SettingsSuite 只能重新实现这三件事，且必然与 EDS 的既有行为跑偏（尤其是无障碍字号与触控目标尺寸）。

## 二、需求清单

### R1 · `EDSInteractionProfile.resolved` 提升为 public

- 文件：`Sources/EasyDesignSystem/EDSAdaptiveEnvironment.swift`
- 行号：13
- 现状：

```swift
public enum EDSInteractionProfile: String, Codable, CaseIterable, Sendable {
    case automatic
    case touch
    case pointer
    case hybrid

    var resolved: EDSInteractionProfile {          // ← internal
```

- 目标：`var resolved` → `public var resolved`
- 理由：上层需要知道"当前实际生效的交互档案"（`.automatic` 会按平台解析为 pointer / touch / hybrid / catalyst），才能做出与 EDS 一致的自适应决策。自己写 `#if targetEnvironment(macCatalyst)` 判断必然与 EDS 不一致。

### R2 · `EDSResolvedMetrics` 整体提升为 public

- 文件：`Sources/EasyDesignSystem/EDSAdaptiveEnvironment.swift`
- 行号：44 – 91（整个类型）
- 现状：`struct EDSResolvedMetrics: Equatable {` + 5 个 `let` 属性 + `static func resolve(...)` + `func interactiveHeight(for:)` 全为 internal
- 目标：
  1. `struct EDSResolvedMetrics` → `public struct EDSResolvedMetrics`
  2. 5 个存储属性 `pagePadding` / `readableContentMaxWidth` / `minimumInteractiveDimension` / `supportsHoverEnhancement` / `showsPersistentAuxiliaryActions` → 各自加 `public let`
  3. `static func resolve(tokens:profile:horizontalSizeClass:)` → `public static func`
  4. `func interactiveHeight(for:)` → `public func`
- **可不提供 `public init`**（只读类型，外部只需消费 `resolve` 的结果，不需要自行构造）
- 理由：这是上层自组装行/页面的核心度量源。缺了它，`minimumInteractiveDimension`（iOS HIG 触控目标硬指标）、`pagePadding`（自适应边距）、`supportsHoverEnhancement`（macOS hover 增强开关）都得自己猜。
- 依赖类型可见性已确认无阻塞：`EDSDesignTokens`（`EDSDesignTokens.swift:517` public）、`EDSAdaptiveLayoutTokens`（`:425` public）、`EDSTypographyTokens`（`:285` public）。

### R3 · `EDSFontRole` 与 `View.edsFont(_:tokens:)` 提升为 public

- 文件：`Sources/EasyDesignSystem/EDSScaledTypography.swift`
- 行号：3（`enum EDSFontRole`）、49–53（`extension View { func edsFont(...) }`）
- 目标：
  1. `enum EDSFontRole` → `public enum EDSFontRole`（**必须一起改，否则 `edsFont` 即使 public 也无法被外部调用——参数类型不可见**）
  2. `func edsFont(_ role: EDSFontRole, tokens: EDSTypographyTokens)` → 加 `public`
- 理由：这是 Dynamic Type 缩放字体的唯一入口。不暴露就只能用 `.font(.body)`，无障碍字号下排版会与 EDS 不一致。
- 注意：`EDSFontSpecification`（:16）与 `EDSScaledFontModifier`（:22）保持 `private` 不变；`EDSTypographyTokens.specification(for:)`（:56）保持 `private extension` 不变。

### R4 ·（可选，建议一并做）`View.edsFont(_ role:)` 便捷重载

- 文件：`Sources/EasyDesignSystem/EDSScaledTypography.swift`
- 目的：让上层不必手工传 `tokens`，直接跟随当前主题：

```swift
private struct EDSThemedFontModifier: ViewModifier {
    @Environment(\.edsTheme) private var theme
    let role: EDSFontRole

    func body(content: Content) -> some View {
        content.modifier(EDSScaledFontModifier(specification: theme.typography.specification(for: role)))
    }
}

public extension View {
    func edsFont(_ role: EDSFontRole) -> some View {
        modifier(EDSThemedFontModifier(role: role))
    }
}
```

- 若判定与现有 `edsFont(_:tokens:)` 语义重复而不做，**不影响 SettingsSuite 落地**（上层可自行传 `theme.typography`）。

### ⚠️ 明确不做：`EDSSettingRow` 保持原样

**前置说明：这条推翻了 SettingsSuite 侧早期的一个提议**（早前提议"删除或重命名 `EDSSettingRow`，因为它归属错位"）。核查后**撤回该提议**，理由是原提议基于错误假设：

| 核查项 | 结果 |
| --- | --- |
| VideoHero / TTSMate 是否在用 `EDSSettingRow` | **未使用**（两仓 grep 均为空） |
| EDS 自身依赖面 | `Tests/EasyDesignSystemTests.swift:27,303`、`README.md`（**6 处，作为公开推荐用法示例**）、`docs/20260905支持多平台技术方案和开发计划.md:23,348`、`Examples/Catalog/EDSDesignSystemGallery.swift`（多处 showcase）、`Examples/PlatformCatalog/PlatformCatalogContentView.swift:197` |

**结论：删除或改名都是破坏性变更，且会打断 README / Examples / Tests，收益为零。保留不动。**

两者并存不冲突，因为语义不同：

| 组件 | 语义 | 能力 |
| --- | --- | --- |
| `EDSSettingRow`（EDS） | **展示型行** | title + subtitle + trailing 任意控件（如 `EDSToggle`），不可点击 |
| `SettingRow`（SettingsSuite 自建） | **交互型行** | 点击执行 / 推入导航 + chevron + hover 高亮 + 选中态 |

### 附：不需要新增 EnvironmentKey

早期曾设想新增 `public extension EnvironmentValues { var edsResolvedMetrics }`，**评估后放弃**，因为 `EnvironmentKey.defaultValue` 需要构造一个默认 `EDSDesignTokens`，会引入"默认 token 是否等于 EDS 默认主题"的语义含混。

上层只需 3 行样板自行求值即可（所需 Environment 值均已是 public）：

```swift
struct SettingRow<...>: View {
    @Environment(\.edsTheme) private var theme
    @Environment(\.edsInteractionProfile) private var profile
    @Environment(\.horizontalSizeClass) private var sizeClass

    var body: some View {
        let metrics = EDSResolvedMetrics.resolve(
            tokens: theme, profile: profile, horizontalSizeClass: sizeClass)
        // …用 metrics.interactiveHeight(for: theme.controlSize.rowMinHeight) 等
    }
}
```

> 顺带记录一个上层必须注意的细节：`minimumInteractiveDimension` 在 `.pointer` / `.automatic`（即 macOS）下解析为 **0**。因此上层**不能**直接把它当 `minHeight` 用，必须走 `metrics.interactiveHeight(for: theme.controlSize.rowMinHeight)` 才能拿到有意义的行高。这个细节请写入 `EDSResolvedMetrics` 的文档注释里，避免下一个使用者也踩。

## 三、约束

1. **不改任何现有行为**：本需求只增加可见性（`internal` → `public`）与可选新增 API，不修改任何计算逻辑、默认值、渲染结果。
2. **不破坏现有公开 API**：不删除、不改名、不改签名。
3. **README / Examples / Tests / docs 必须继续编译通过**，无需修改它们（R4 若做，只在 `EDSScaledTypography.swift` 内新增代码）。
4. **四平台都要过**：iOS 17 / iPadOS 17 / macOS 14 / Mac Catalyst 17。
5. **版本号建议：`0.2.0` → `0.2.1`**（**不是** `0.3.0`）。理由见下。

   **为什么走 patch 位**：本次改动是「只提升可见性 + 新增 1 个便利 API」，**零行为变更、零签名破坏、零删除**，没有任何调用方需要改代码。semver 官方对 `0.y.z` 的规定是 *"Major version zero (0.y.z) is for initial development. Anything MAY change at any time."* —— 0.x 阶段版本位没有强制分配规则，用 patch 位承接「向后兼容的新增」是常见实践。

   更实际的一条：EDS 现有宿主（如 `SwiftHelpCenter/Package.swift`）的约束是 `.upToNextMinor(from: "0.2.0")`，其**解析上界是 `< 0.3.0`**。因此：

   | 发布版本 | 现有宿主能否自动获得新 API | 需要改约束的宿主数 |
   | --- | --- | --- |
   | `0.2.1` | **能**（落在 `0.2.0 ..< 0.3.0` 区间内） | **0** |
   | `0.3.0` | 不能（宿主被锁在 `0.2.x`） | 每个想用新 API 的宿主都得改 |

   本次改动的目的就是「让上层能拿到 EDS 已有的能力」，越无感越好，所以 patch 位更合适。

   **建议同时在 CHANGELOG 开头固化版本位判据**，以后不必每次重新讨论：

   > - **patch（`0.2.x`）**：向后兼容的新增、纯可见性提升、Bug 修复
   > - **minor（`0.y.0`）**：有架构意义的节点 / 有行为变更 / 引入新的对外模型（如 `0.2.0` 的多平台支持）
   >
   > ⚠️ 此规则**在 `1.0.0` 之后失效** —— 按标准 semver，新增 public API 必须走 minor。

6. **顺手修一个 CHANGELOG 的历史遗留问题（低成本，建议一并做）**：当前 `CHANGELOG.md` 中，`## Unreleased` 段仍挂着多平台那一整批条目（"支持 iOS 17、iPadOS 17…"、"新增 Touch、Pointer、Hybrid 自动交互档案"等），但这些内容**已经包含在 `0.2.0` tag 里** —— `git show 0.2.0:CHANGELOG.md` 证实 tag 处的 CHANGELOG 也是这个样子（tag 打在 `Supports iOS platform` 提交上）。即 **tag 与 CHANGELOG 未对齐**，现在追溯「0.2.0 到底包含什么」只能靠猜。

   建议：把 `## Unreleased` 现有条目**原样搬进新开的 `## 0.2.0` 段**，让 `## Unreleased` 空出来承接本次 `0.2.1`。纯文档整理，不动任何代码。

```swift
import EasyDesignSystem
import SwiftUI

struct ProbeRow: View {
    @Environment(\.edsTheme) private var theme
    @Environment(\.edsInteractionProfile) private var profile
    @Environment(\.horizontalSizeClass) private var sizeClass

    var body: some View {
        let metrics = EDSResolvedMetrics.resolve(
            tokens: theme, profile: profile, horizontalSizeClass: sizeClass)
        let resolved = profile.resolved                       // R1
        Text("probe")
            .edsFont(.bodyStrong, tokens: theme.typography)   // R3
            .frame(minHeight: metrics.interactiveHeight(for: theme.controlSize.rowMinHeight))
            .onAppear { print(metrics.minimumInteractiveDimension, resolved) }
    }
}
```

- [ ] 上面这段代码在 **macOS / iOS 两个平台**均编译、运行无警告
